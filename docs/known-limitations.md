# Known limitations

What Nerda can't do yet, or does only through WebKit SPI that may go. The decisions behind each are in [decisions.md](decisions.md).

- Extensions are off until `Extensions.available` is set again; then they are opt-in and need a restart after the master switch changes. Compatibility remains at Safari's level: `webRequest` doesn't work in MV3; some (e.g. Vimium C) don't open.
- DRM: FairPlay only (Netflix etc. as in Safari).
- Video files (#36): one written in the page's HTML (`<video src>` in its markup) loads as WebKit has it, as watching every page's changes to find one would cost them all. A video loaded through Nerda reads as buffered to its end, and AirPlay of it is untried. Its requests don't pass WebKit's content blockers, so a blocked ad file a page's script names still loads (an ad's address is usually blocked before it is known). The scheme is made secure through SPI (`_registerURLSchemeAsSecure:`); should it go, pages keep WebKit's own loading.
- Full screen: inside the window, as in Chrome (WebKit's own moves the page into a separate window and can't be turned off). A site's own `:fullscreen` CSS rules don't apply; the button of a plain `<video controls>` still opens WebKit's separate window. WebKit SPI (`_setWindowOcclusionDetectionEnabled:`) keeps video playing during the full-screen animation; should it go away, video only pauses for a moment during the animation again.
- Address bar colour: taken from WebKit's own sample of the page's top edge (SPI `_sampledPageTopColor`, as Safari's); should it go away, the bar falls back to the page's `theme-color`, which some sites (GitHub, YouTube) set to a colour their top doesn't use.
- Page edges: a page scrolled to its end stays put, as in Chrome, through WebKit SPI (`_setRubberBandingEnabled:`, as each page is made); should it go away, pages bounce past their edges again. A box that scrolls inside a page (a chat, a code view) still bounces: WebKit gives no switch for those.
- AutoFill knows a form's boxes by their `autocomplete` token or English words; a box named only in another language isn't offered anything. A form sent without a new page loading (a checkout that stays on one page) isn't offered to save, and card boxes in a payment provider's frame are left to it.
- Passwords fill the requesting frame and check its own host and transport before filling. Native passkeys require Apple's approved browser entitlement and a matching provisioning profile; ordinary builds retain password and extension fallback. Notarization is a separate process. Without an Apple Development certificate (Team ID), macOS asks for the login password once after each new build, the first time a password is picked or saved; `build.sh` uses the certificate by itself when there is one.
- Sign-ins with a service (Google, GitHub…) are told by where the page goes, from a list of known services: one through a service not on it, or started inside the service's own frame on the site (Google One Tap), isn't offered, and picking a saved one presses the site's button only when the site draws it itself, not in the service's frame. A service pop-up that closes itself after you cancelled (Google's, Telegram's) can still be offered. The account is known when it is typed at the service or picked in Google's list; otherwise the card asks for it.
- Draft protection counts only what the person did, not the page's own script, and never a password or search box. In the main frame, a field the person edited counts while it is still on the page and still differs from how it loaded; it is checked again on input, shortly after Enter, a click or a submit, and when the tab is shown or hidden, so a chat app that empties its box after sending lets the tab sleep and close quietly again. A file dropped on the page, and any edit inside a frame (which can't be checked again from the page), keep the tab awake until a new document commits. Nerda cannot tell whether an arbitrary site's autosave has finished. Closing the tab or window, quitting, typing an address, Back, Forward and Reload ask first; links and the page's own navigations are left to its beforeunload, as in Chrome and Safari, so a sign-in's redirect never asks. Crashes and forced termination can still lose unsaved work.
- Per-site ad-blocking exceptions use WebKit's document preferences SPI, limited to Nerda's lists (element hiding and the dangerous-site lists too, which is how a refused dangerous site is opened anyway); extension rules remain active. If that SPI is unavailable, the per-site switch is disabled and global blocking remains available.
- Element hiding takes plain CSS selectors only: uBlock's and AdGuard's procedural filters and scriptlets are skipped, and `$generichide` turns off all hiding on its pages, not only the generic. A selector WebKit's CSS can't read is skipped by WebKit alone. The dangerous-site page names the list by reading the chosen lists' kept copies when WebKit refuses a page; anything else that refuses a page keeps WebKit's own words.
- Site notifications reach Nerda through WebKit's C notification provider (a page's `new Notification`) and its data store delegate (a service worker's), both SPI, as Safari's; they show as the Mac's own. Should either go, sites are told no and the Notifications row is hidden. Answers to a site's questions (notifications, camera, microphone, location) are kept per site; a frame from another site still gets WebKit's own camera and location question, so its answer isn't kept for the page around it.
- Profiles: extensions run in Personal's window only, not in its secondary windows (#35) either. A site's notification permission reaches WebKit's pages as one list for all profiles, though each profile's own answer still decides what shows. Site icons are one cache for all, so deleting history in one profile can drop icons another fetches again. A deleted profile's website data that WebKit won't remove at once (a page still closing) is removed at the next launch.
- Download resume data stays in memory for this running session. Resuming requires server support; Retry accepts only HTTP(S) GET/HEAD requests without a body, so a purchase or upload is never repeated silently.
