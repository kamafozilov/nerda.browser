# Technical decisions

Reference: [driceroland/Search](https://github.com/driceroland/Search) (MIT). We follow the same path.

## Adopted

| # | Layer | Decision | Why |
|---|---|---|---|
| 1 | Platform | macOS only | I use macOS myself; on Windows/Linux, Chrome extensions only fully work with Chromium, which goes against the "lightweight" goal |
| 2 | Engine | WebKit (`WKWebView`) | Ships with the system: the app is a few MB, without Chromium's 300 MB |
| 3 | Language | Swift | The only natural choice for Apple APIs |
| 4 | UI | SwiftUI, plus AppKit where needed | Search does it this way and it works |
| 5 | Project | SwiftPM (`Package.swift`) + `build.sh` assembles the `.app` bundle | Plain text files only; Xcode not required (Command Line Tools are enough) |
| 6 | Minimum OS | macOS 15.4 | `WKWebExtensionController` exists from this version on (checked in a build) |
| 7 | Chrome extensions | `WKWebExtension` + installing `.crx` from the Chrome Web Store, after Search: the store's page gets an Add to Nerda button (`WebStore.swift`); the CRX3 signature is checked against the extension's id before unpacking (`Crx.swift`); a script put in each extension at install fills in the Chrome APIs WebKit lacks and mends where it differs (`ExtensionShims.swift`); popups are Nerda's own popover. Buttons at the right of the address bar, as in Chrome. The regular window's tabs only, not incognito. Turned off in every build for now (`Extensions.available`, 2026-10-14): no controller, store button, address bar button or settings page, whatever the saved switch says. Installed extensions and their settings stay on disk for when it turns back on | Speed and reliability take priority over Chrome compatibility. That is where the main users come from. Search's layer is the working answer to WebKit's gaps; a popup's page goes by its own address (Dark Reader answers only that), and hears the worker's messages over a channel, which WebKit keeps from it |
| 8 | Ad blocking | EasyList and EasyPrivacy filters compiled to `WKContentRuleList` in a helper process, refreshed every 4 days in the background (`NSBackgroundActivityScheduler`, never at launch unless there is no list yet), asking only for lists changed since (ETag, Last-Modified) and compiling only when the lists or Nerda changed. Network filters block loads; element-hiding filters (`##`, `domain##`, `~domain##`) become `css-display-none` rules in lists of their own, one rule per selector, after their `#@#` exceptions are applied; `$elemhide`, `$generichide` and `$document` exceptions turn all hiding off on those pages; uBlock's and AdGuard's own selectors (`#?#`, `+js`, `:has-text`…) are skipped. Main-frame navigation is always allowed by ad lists; the lists of dangerous sites (Phishing URL Blocklist, Online Malicious URL Blocklist, uBlock filters – Badware risks, CERT.PL's Warning List) are compiled into lists of their own without that exemption, their `$doc` blocks kept, so a site on them is refused as a page, and the tab says which list it is on and that the site's Ads and trackers switch lets it open. Generic blocks apply only to third-party requests, and known challenge services are exempt. Settings can disable blocking. See [adblock audit](adblock-audit.md) for translation limits and evidence | WebKit filters requests and hides elements without per-request Swift or JavaScript. Versioned compiled caches prevent reuse of unsafe rules; failed updates keep the last compatible list, and navigation never waits for a download. WebKit's ignore-previous-rules undoes everything before it in its own list, hiding included, so hiding and the dangerous sites live in lists the page exemption isn't in. Scriptlets and procedural cosmetic filters are not supported |
| 9 | RAM | Put unused tabs to sleep (the web view is destroyed, a snapshot stays) after 30 minutes out of sight (Settings › Tabs: 15 minutes to 4 hours, or never), at once under memory pressure, and after 10 minutes when one takes over 500 MB. Edited pages and active media capture stay awake. Pinned tabs load at launch after the tab on screen, one at a time, or not until opened (Settings › General); they sleep only when the Mac runs out of memory or one takes over 500 MB | 100–300 MB per tab is the main cost. The same six sites took 1.63 GB in Nerda and in Safari alike (2026-09-26): what was left was pinned x.com and Gmail at 650–750 MB each, never asleep, and one WebGL tab at 2.2 GB |
| 10 | Storage | JSON files, in one folder | No server, no account |
| 11 | Passwords | Nerda's own store: the passwords are one item in the login keychain (`Nerda Passwords`), the site and user names they go with are `accounts.json` beside the history; those in Passwords/Safari come in once from a CSV via File › Import Passwords… | Safari's passwords sit behind an Apple entitlement; macOS (AMFI launch constraint) won't start the iCloud Passwords helper from Nerda. The keychain asks again after every build without a Team ID: as one item, and with the names outside it, that is one question, and only once a password is picked or saved, never for listing accounts |
| 12 | External dependencies | None, Apple frameworks only | |
| 13 | Codebase | Written from scratch; needed parts (e.g. `Crx.swift`, `ExtensionShims.swift`) are taken from Search, with the MIT license text | The structure should be our own |
| 14 | Tools | Xcode (Instruments, debugger), `swift format` (in the toolchain) | Command Line Tools are enough to build |
| 15 | Entry point | AppKit (`NSApplication`, `main.swift`); SwiftUI views through `NSHostingView` | Full control over windows; a SwiftUI `App` always requires some Scene |
| 16 | Concurrency | Swift 6, default isolation `MainActor` | AppKit and WebKit are on the main thread anyway; background work is marked explicitly |
| 17 | Versions | SemVer tags `vX.Y.Z`; 0.0.x, one patch step per release, until the public launch as 1.0.0; `CHANGELOG.md` in Keep a Changelog form | See [releasing.md](releasing.md) |
| 18 | Dev and release | Nerda Dev (debug) is a separate app: its own bundle id, data folder and keychain item (`Edition.swift`, `build.sh`) | Working on Nerda must not touch the data of the Nerda in use |
| 19 | Updates | Our own updater (`Updater.swift`, after Search's): GitHub Releases carry the DMG and a ZIP; a newer ZIP is checked by SHA-256, bundle id, version and a Developer ID signature of the same team, then swapped in | No framework (#12): Sparkle would add a framework, an EdDSA key and a copy step to build.sh, for what about 300 lines do |
| 20 | Signing | Releases: Developer ID Application, one fixed team (`NERDA_TEAM` in the untracked `release.env`), hardened runtime, notarized and stapled, universal (arm64 + x86_64). Development: the Apple Development certificate, as before | Opens on any Mac without warnings; the team is fixed because the updater only accepts its own |
| 21 | New tab pictures | CC0 photos from Wikimedia Commons, bundled (`assets/backgrounds`, credits there), 2880 px HEIC, one for now, more as they are chosen; one a day, decoded once off the main thread, big enough to fill the largest screen. Your pictures are copied into the data folder (`Wallpapers`), as many as you add, as HEIC up to 6144 px: sharp on a 6K screen, without keeping a camera's whole picture | Offline and private: no API key, no request per new tab, as Unsplash or Bing would need. CC0 needs no credit on screen and no licence to ship with it |
| 22 | Performance | Measured, not guessed: `./bench.sh` (Bench.swift) times launch, pages opening, tab switches and wakes, typing in the address bar, memory and CPU at rest (`./bench.sh web` adds Speedometer, JetStream, MotionMark). WebKit is set up as Safari has it, through SPI that falls back to plain WebKit if it goes: one process pool for every tab, a page process kept ready, sites connected to while their address is typed, DNS prefetch, hidden pages' timers slowed more the longer they stay hidden, a background CPU limit that puts a runaway hidden tab to sleep, and service workers ended 30 s after pages sleep or close only while no extension is loaded (the SPI ends all workers, including extension backgrounds) | Left alone, each tab made its own pool and read every font on the Mac first (~30 ms on the main thread per tab); the rest is what keeps Safari quick and light |
| 23 | Frame rate | Pages drawn at the screen's own rate, up to 120 a second on a ProMotion screen, as in Chrome; in Low Power Mode, WebKit's 60, as in Safari. Through SPI (the `PreferPageRenderingUpdatesNear60FPSEnabled` feature flag), set as each page is made | WebKit holds pages near 60 even on a 120 Hz screen, where Chrome, Arc and Firefox draw at 120. A page that is standing still costs nothing either way; one that animates draws twice as often. Measured (`./bench.sh`, a canvas redrawn every frame): 60 → 120 frames a second for 28% → 43% CPU, so Low Power Mode keeps it at 60 |
| 24 | Incognito | A window of its own (`Incognito.swift`), its tabs on a `WKWebsiteDataStore.nonPersistent()` shared by all incognito windows until the last closes, as in Chrome; no history, session or icons written, and nothing from history suggested. Always dark, on a plain grey in place of the glass, with a muted violet accent. They lock together (screen lock, sleep, a minute in the background) behind `LocalAuthentication` (Touch ID or the Mac's password), as Safari's private windows do | WebKit keeps a non-persistent store's cookies, cache and storage in memory only; the look makes it plain which window is private |
| 25 | Trying it on screen | On this Mac, in the background: Nerda Test (`./build.sh test`, data of its own) opens behind the window in use and is driven through its window's accessibility elements with cua-driver (trycua/cua, MIT, telemetry off), never with the pointer, the keyboard or by coming forward (AGENTS.md has the how). Pictures of changes are welcome in a pull request, not required | Agents took the owner's screen, mouse and keyboard in the middle of a video or a chat (Orca), so that stays ruled out. A test VM (Tart) did it apart, but its 4 GB of memory, 67 GB of disk and one-agent-at-a-time waits weighed on the work more than they saved: removed 2026-09-26. cua-driver posts to one app's window and reads its accessibility tree, which leaves the owner's pointer and front app as they are (checked); a click by position into a page doesn't land, so tests go by element |
| 26 | Direction | Nerda grows into one place to work from without leaving it, as a universal tool: it fits around the services and apps people already use (their web apps, accounts, files) and ties them together, rather than building its own mail, chat, calendar or the like | Rebuilding existing products is years of work and would break the lightweight goal (#2, #12); the web apps are already there, what's missing is one place that holds them together |
| 27 | Bookmarks | As in Arc: a bookmark opens in a tab of its own that stays in the bookmark's place (`Tab.bookmark`), not in the list; closing it keeps the bookmark, which opens afresh at its address. Folders nest. Kept in `bookmarks.json`, written whole on each change. Imported from the Netscape HTML file every browser exports | Keeping tabs to come back to was what was asked for, not a list of links that open new tabs. One HTML format covers Chrome, Safari, Firefox and Arc; reading Safari's own file would need Full Disk Access |
| 28 | Text selection | Drawn as Chrome draws it, on the text only (`Selection.swift`): WebKit's own selection colour is made clear by a user style sheet (SPI), and the selection is drawn as a CSS Custom Highlight in WebKit's colours. A site's own `::selection` colour, text fields, images and the insides of components stay WebKit's to draw | WebKit fills a selection's gaps out to the page's edges and between blocks, and has no setting against it (checked in its source: the old `SelectionPaintingWithoutSelectionGaps` setting is gone). A page highlight colours text only |
| 29 | Feedback and crashes | Help › Report a Problem… and Suggest an Idea…, and a card in the sidebar after a crash, show the report and, once the person continues, open a new GitHub issue in a tab, filled in for them to finish and submit (`Feedback.swift`). The report travels in the issue page's address, so it reaches GitHub as that page opens: the preview comes first for that reason. Crashes come from MetricKit at the next launch; each release carries its `Nerda.dSYM.zip` for `symbolicate.sh` | No server, account or key of Nerda's (#10, #12), and nothing leaves the Mac before the person has seen it and continued. GitHub needs an account of the person's own, the price of not running a server |
| 30 | Translation | Apple's Translation framework, on this Mac (`Translate.swift`), as Safari translates. The page's language is what its `<html lang>` says, or else NaturalLanguage's guess from its first thousand characters; a page in none of your languages (Settings › General) gets a Translate button in the address bar and View › Translation. Nerda's script, in its own world, sends the page's text a block at a time (a paragraph, a list item, a cell: the inline content between blocks), its links, bold and code marked by number, `⟦1⟧…⟦/1⟧`, and puts each element back round its own words in the translation's order; marks that come back broken leave the sentence whole without its links. Ten blocks or 500 characters a batch, nearest the screen first and the page's `main` before its menus, tooltips and alt text last, each written back as it comes; it takes up what the page adds, and puts back the very nodes and words for Show Original; at most 100,000 characters a page. The session comes from SwiftUI's `translationTask`, one per window for the tab on screen; a tab keeps translating the pages it opens until Show Original | Nothing leaves the Mac and there is no server, account or key (#10, #12). `translationTask` works from macOS 15 and lets the Mac ask to download a language itself; macOS 26's `TranslationSession(installedSource:target:)` only takes languages already downloaded. The top frame only, as frames are other sites'. Text node by text node, a sentence split by links came back in pieces ("one Web browser Or one Web browser"); the model keeps the marks (241 of 241 blocks of French and German Wikipedia, taking a close written `⟧/1⟧` and a lost empty mark). Measured on an M1 Pro with the high-fidelity model macOS 26.4 uses by default (`.lowLatency` was not downloaded): about 60 characters a second, one request after another whether sent singly, in batches or side by side, so the first screen of a Wikipedia article (about 3,000 characters) takes 45-55 seconds; small batches only decide what comes first |
| 31 | Reader | Nerda's own article extractor (`Reader.swift`), in JavaScript run in a content world of Nerda's: each paragraph scores the box it sits in by its length and commas, less what of it is links, with names like article, content or post counting for a box and comment, sidebar, nav, share or related against it; the best box, and those beside it that score near it, are copied into a page of Nerda's tag by tag from a short list (lazy-loaded images at their real address), with the title, byline, site and date from the page's meta tags and JSON-LD. A small check after each page loads, when the page is idle, decides whether to offer it. The article shows over the tab's page in a view of its own with no scripts and a strict CSP, as Safari's Reader takes the page's place | Mozilla's Readability is the usual answer, but it is a dependency (#12), and much larger than what is needed here; Safari's own Reader isn't open to other apps. Over the page rather than in it, the site's scripts and styles can't reach the article, and leaving Reader is instant: the page under it was never reloaded |
| 32 | Import from a browser | File › Import From Browser… reads another browser's own files on this Mac (`BrowserImport.swift`): a copy of each SQLite file (Chromium's History, Firefox's places.sqlite) read with the system's SQLite, and Chromium's Bookmarks JSON. History is merged into Nerda's (counts added, the later date kept), no older than Settings keeps it and no more than its limit; bookmarks go in a folder of their own. Safari's history is not read | No export step for the person, and no dependency: SQLite ships with macOS. A copy, as the browser keeps its files open and locked. Safari's files need Full Disk Access, too much to ask for an import; its bookmarks come from the file it exports (#27) |
| 33 | AutoFill | Addresses and cards are Nerda's own: `autofill.json` beside `accounts.json`, and the card numbers one item in the login keychain (`Nerda Cards`), as passwords are (#11); a card's security code is never kept. The passwords' script, in the same script world, tells a form's boxes by their `autocomplete` token or else the English words in their name, id and label, lists what is kept under the box the caret is in, and fills that run of the form (`AutoFill.swift`). Only the top frame and frames of its origin; cards only over https, and only after Touch ID or the Mac's password. A form's new address or card is offered to keep once the next page loads, never in incognito. Settings › AutoFill turns each on or off and edits them | One script, one list under a box and one keychain question per build, as for passwords; everything but the number outside the keychain, so listing and the settings never ask it. A frame from another site (an ad, a payment provider's) is not the page's to fill |
| 34 | Profiles | As in Safari: Settings › Profiles makes one, with a name, a symbol and a colour, and renames or deletes it. Each keeps its history, bookmarks, open tabs, site settings and the names of its saved passwords in a folder of its own (`Profiles/<id>`), its cookies and website data in a `WKWebsiteDataStore(forIdentifier:)`, and its passwords in a keychain item of its own (`Profile.swift`). Personal, the first, keeps what there was before profiles where it was, so nothing moves. One window a profile, as Nerda has one regular window: File › New Window and the top of the sidebar's menu open it, its menu button wears the profile's symbol, and those left open come back at launch. Links from other apps open in the window of a profile used last. Deleting one closes its window and removes its folder, keychain item and data store. With Personal alone none of this shows or runs, but Settings › Profiles. Nerda's own settings, AutoFill, downloads and the new tab's pictures are shared by all | Work and personal accounts of one site signed in side by side, with no account or server (#10). A keychain item each rather than a profile tag in one: the vault writes its item whole and keeps only the logins its own names list, so two profiles in one item would each wipe the other's; with an item each the vault stays as it is, and deleting a profile's passwords is one call. A store per identifier is WebKit's own way, from macOS 14, to keep cookies, cache and storage apart on disk |
| 35 | Moving a tab to a window of its own | Move to New Window (a tab's menu, Window menu) or a tab dragged off its window makes a secondary window of the same browsing (`Browser.isSecondary`, `Windows.moveToNewWindow`), filling the display it is let go on, or from the menu the next display. The `Tab` object moves with its `WKWebView`, which is never reloaded. A secondary window shows tabs only: the pinned sites and bookmarks stay in the profile's own window, and settings, history and bookmarks opened from it go there. A pinned site or a bookmark's tab moved out leaves its tile or row behind, asleep. Dragged off its list, the tab's place closes up and a card of it (the hover card's) follows the pointer in a panel of its own across displays; over another window's tabs a gap opens with the tab in it, and it lands there (`TabDrag`). A tab let go on another window of the same browsing joins it; Window › Merge All Windows brings them back. Each secondary window is saved with its frame (`<profile folder>/Windows/<id>.json`) and opens again on its display at launch; closing one puts its tabs in the profile window's Recently Closed | For several displays, as every browser allows. Arc, Zen and Safari show the pinned tabs in every window, which keeps a page of each pinned site per window and doubles their memory; Chrome ties them to the window they were pinned in. One home for pins and bookmarks keeps one page each. Moving the page rather than reopening its address keeps a video playing and a form's text |

## Known limitations

- Extensions are off until `Extensions.available` is set again; then they are opt-in and need a restart after the master switch changes. Compatibility remains at Safari's level: `webRequest` doesn't work in MV3; some (e.g. Vimium C) don't open.
- DRM: FairPlay only (Netflix etc. as in Safari).
- Full screen: inside the window, as in Chrome (WebKit's own moves the page into a separate window and can't be turned off). A site's own `:fullscreen` CSS rules don't apply; the button of a plain `<video controls>` still opens WebKit's separate window. WebKit SPI (`_setWindowOcclusionDetectionEnabled:`) keeps video playing during the full-screen animation; should it go away, video only pauses for a moment during the animation again.
- Address bar colour: taken from WebKit's own sample of the page's top edge (SPI `_sampledPageTopColor`, as Safari's); should it go away, the bar falls back to the page's `theme-color`, which some sites (GitHub, YouTube) set to a colour their top doesn't use.
- Page edges: a page scrolled to its end stays put, as in Chrome, through WebKit SPI (`_setRubberBandingEnabled:`, as each page is made); should it go away, pages bounce past their edges again. A box that scrolls inside a page (a chat, a code view) still bounces: WebKit gives no switch for those.
- AutoFill knows a form's boxes by their `autocomplete` token or English words; a box named only in another language isn't offered anything. A form sent without a new page loading (a checkout that stays on one page) isn't offered to save, and card boxes in a payment provider's frame are left to it.
- Passwords fill the requesting frame and check its own host and transport before filling. Native passkeys require Apple's approved browser entitlement and a matching provisioning profile; ordinary builds retain password and extension fallback. Notarization is a separate process. Without an Apple Development certificate (Team ID), macOS asks for the login password once after each new build, the first time a password is picked or saved; `build.sh` uses the certificate by itself when there is one.
- Draft protection counts only what the person did, not the page's own script, and never a password or search box. In the main frame, a field the person edited counts while it is still on the page and still differs from how it loaded; it is checked again on input, shortly after Enter, a click or a submit, and when the tab is shown or hidden, so a chat app that empties its box after sending lets the tab sleep and close quietly again. A file dropped on the page, and any edit inside a frame (which can't be checked again from the page), keep the tab awake until a new document commits. Nerda cannot tell whether an arbitrary site's autosave has finished. Closing the tab or window, quitting, typing an address, Back, Forward and Reload ask first; links and the page's own navigations are left to its beforeunload, as in Chrome and Safari, so a sign-in's redirect never asks. Crashes and forced termination can still lose unsaved work.
- Per-site ad-blocking exceptions use WebKit's document preferences SPI, limited to Nerda's lists (element hiding and the dangerous-site lists too, which is how a refused dangerous site is opened anyway); extension rules remain active. If that SPI is unavailable, the per-site switch is disabled and global blocking remains available.
- Element hiding takes plain CSS selectors only: uBlock's and AdGuard's procedural filters and scriptlets are skipped, and `$generichide` turns off all hiding on its pages, not only the generic. A selector WebKit's CSS can't read is skipped by WebKit alone. The dangerous-site page names the list by reading the chosen lists' kept copies when WebKit refuses a page; anything else that refuses a page keeps WebKit's own words.
- Site notifications reach Nerda through WebKit's C notification provider (a page's `new Notification`) and its data store delegate (a service worker's), both SPI, as Safari's; they show as the Mac's own. Should either go, sites are told no and the Notifications row is hidden. Answers to a site's questions (notifications, camera, microphone, location) are kept per site; a frame from another site still gets WebKit's own camera and location question, so its answer isn't kept for the page around it.
- Profiles: extensions run in Personal's window only, not in its secondary windows (#35) either. A site's notification permission reaches WebKit's pages as one list for all profiles, though each profile's own answer still decides what shows. Site icons are one cache for all, so deleting history in one profile can drop icons another fetches again. A deleted profile's website data that WebKit won't remove at once (a page still closing) is removed at the next launch.
- Download resume data stays in memory for this running session. Resuming requires server support; Retry accepts only HTTP(S) GET/HEAD requests without a body, so a purchase or upload is never repeated silently.
